Second bug hunt (12 Oct 2026), most serious first:
- [x] Repeating tasks disappear from LINE after you tick them: a repeating task only resets to "not done" when the dashboard is opened after its deadline. Until then it stays "done", so the morning letter and the "starting soon" reminders skip the next round. Example: a daily 20:00 task ticked on Monday is missing from Tuesday's 08:00 letter unless you opened the app on Monday night. Done: a database job every 5 minutes moves them to their next round (same rule as the app), only for users linked to LINE with the morning letter or reminders on; the app still does it when opened
- [x] Blocking the bot on LINE left the account linked, so the server kept sending messages (and doing work) for someone who could no longer receive them. Done: when LINE reports the bot was blocked, the webhook clears that LINE link; the link code stays, so adding the bot back and sending it again links the same account
- [x] "Clear Past" on the Events page can delete events that are still running: "past" only looks at the start time, so an event that started yesterday and ends next week is listed under Past Events (while Home shows it under "In progress...") and "Clear Past" deletes it. Done: an event is past only once it has ended; running events have their own "In Progress" group and count tile on the Events page, and Clear Past leaves them alone
- [x] "Clear Completed" deletes repeating tasks for good: a repeating task ticked done for this round counts as completed, so clearing removes the whole series instead of letting it come back next round. Done: "Clear Completed" deletes only one-time tasks; ticked repeating tasks stay until their next round starts
- [x] Undo after "Clear Completed" / "Clear Past" can bring items back twice: the Undo button makes new copies (new ids), but Recent Changes still lists the original "deleted" entries, and undoing one of those puts the original back too. The copies also lose their drag order and creation date. Done: Undo puts back the original rows (same ids, order and dates) and removes their "deleted" entries from Recent Changes; Undo appears once the clear has gone through
- [x] Changing the start time while editing resets the deadline: on both Tasks and Events, any change to Start sets the deadline to start + 5 hours, even when the item already had its own deadline (e.g. moving the start of a week-long task cuts it to 5 hours without saying so). Done: the deadline follows the start only while it is empty or still the filled-in value (start + 5 h), so a deadline set by hand is kept
- [x] Two scheduled LINE functions depend on a deploy flag nobody wrote down: `supabase/config.toml` marks only line-webhook, send-line-daily and cleanup-attachments as callable without a login. send-line-overdue and send-line-reminders (and line-bot-info, line-rich-menu) are not listed. They are correct on the live project today (checked), but deploying them without `--no-verify-jwt` would make the cron calls fail with 401 and the nudges and reminders would stop with no visible error. Suggest: add those four to `config.toml` with `verify_jwt = false`
- [x] The attachment clean-up almost never deletes anything, and Recent Changes grows forever: every edit saves the old version (with its attachments) in the activity log, the clean-up treats files listed there as still in use, and the log is never trimmed (the app shows only the last 10). Done: the nightly job first removes Recent Changes entries older than 30 days, then deletes files nothing points to anymore
- [x] A LINE nudge that fails to send is never retried: missed-deadline nudges and the morning repeats are marked "sent" before the push. If LINE refuses both the card and the plain-text version, that nudge is lost. Suggest: remove the "sent" mark when both sends fail, so the next 5-minute check tries again
- [x] Copying a task or event drops "Notice before": Copy and the select-mode batch copy leave out that setting, so the copy gets no day-before message. Suggest: copy `notice_before` too
- [x] Repeating tasks that start between 00:00 and 00:15 (Thai time) never get a "starting soon" reminder: the check 10–15 minutes ahead runs before midnight but only looks for repeats on the current day. Suggest: also check the next day's repeat when the window crosses midnight
- [x] Monthly repeats on the 29th–31st drift: renewing a task due 31 Jan moves it to 28 Feb, then 28 Mar, 28 Apr… for good. Done: tasks remember their first deadline (`recurrence_anchor`) and every repeat is counted from it, in the app and in the LINE messages
- [x] Security (low): the LINE functions trust the file paths stored in a task or event and sign them with full access. Someone who changes their own item through the API to point at another account's file would get that file sent to their LINE. The paths contain a random id, so they would need the exact path. Suggest: only send files whose path starts with the item owner's user id
- [x] LINE Settings: the refresh-code button also unlinks LINE, with no warning. After linking in LINE, "Not linked yet" stays on screen until the page is reloaded. Done: while linked, the button asks first (Lulyssia's confirm dialog), and Settings checks the link again when the app comes back into view
- [x] Turning off the "Daily message" also quietly turns off "Notice before" and the daily missed-deadline repeats: both only go out with the 08:00 run, which skips anyone with the daily message off. The "Notice before" switch on each task and event still shows and promises a heads-up. (It is also shown on repeating tasks, which never get one.) Done: the day-before notice has its own on/off (Settings switch, LINE "notice on" / "notice off"), the missed-deadline repeats follow only "overdue on/off", the 08:00 run sends each part by its own switch, and repeating tasks now get the notice too
- [x] Drag to reorder ("User sort") on Tasks, Events and Interests uses mouse-only dragging: those lists have no touch handling (unlike the Home cards, which do), so on many phones the cards can't be dragged at all. Done (confirmed on a phone): press and hold a card to pick it up, then drag; a quick swipe still scrolls
- [x] Scrolling on a phone can shuffle Home's four count tiles: any touch on a tile starts a drag right away, and moving the finger (even a normal up/down scroll) picks a drop target by left/right position only. On a phone the tiles wrap into two rows, so the tile below in the same column also matches, and letting go swaps them. The new order is saved. Suggest: ignore mostly-vertical moves (like the Recent Changes swipe does) and pick the target by both position axes, or start the drag only after a long press. Done: first by ignoring up/down moves, which also blocked moving a tile to the other row; now press and hold, then drag in any direction
- [x] A short connection drop can throw away an open form: when the app comes back into view it reloads its data, and if that reload fails (e.g. the phone is briefly offline), the whole dashboard is replaced by "Something went wrong… please refresh". Any open add/edit form and what was typed in it is lost, even though the data already on screen was fine. Suggest: show the error screen only when there is no data at all, and a small "couldn't refresh" toast otherwise
- [x] Events are sorted by their deadline, not their start time: the default sort "Deadline (soonest)" (and "Request Lulyssia help") orders events by the optional deadline field. An event tomorrow with no deadline is listed after one next month that has one. Done: on the Events page the date sorts are "Start time (soonest/latest)" and use the start time (the deadline only if there is no start); Tasks and Interests keep deadline sorting
- [x] Found when reviewing the branch: for a repeating task whose start comes days before its deadline, LINE moved the start forward on its own while the app keeps it the same distance before each new deadline, so they disagreed after a short month (e.g. 26 Feb in the app, 28 Feb in LINE). Done: LINE now works out the start from that round's deadline, like the app
- [x] Found when reviewing the branch: a repeating task ticked for today before 08:00 got no day-before notice for tomorrow's round (the 08:00 run only read unfinished tasks). Done: the run also reads ticked repeating tasks and only skips the round that was ticked

Third check (13 Oct 2026), after the fixes above:
- [x] Automatic renewals fill up Recent Changes: every time a repeating task moves to its next round (by the dashboard, or now by the database job every 5 minutes), it is recorded as an "updated" entry. With a few daily repeating tasks, most of the 10 entries Recent Changes shows are renewals, pushing out real edits. Undoing one puts the task back to its old round (and ticked), and the job moves it forward again within 5 minutes. Done: renewals are no longer recorded; the dashboard and the job both renew through one database routine, which marks its changes so the activity-log trigger skips them
- [ ] README is out of date: the "Scheduled jobs" table is missing `renew-recurring-tasks` (every 5 minutes), the cleanup job's line doesn't say it also trims Recent Changes to 30 days, `send-line-daily` is described as only the digest and notice (it also sends the missed-deadline repeats, each part by its own switch), and the LINE webhook's unlink-on-block isn't mentioned. Suggest: update those lines (no decision needed)
- [x] New items land in second place in "User sort": new, copied and restored items get order number 0, the same as the item at the top, and the tie goes to the older one. So a new item appears second, not first or last. Done: new and copied items get the number before the current first item, so they show at the top (restored items keep their old place)
- [x] Home "Today's Tasks" shows a task twice when it both starts and is due today (one "Deadline" card and one "Starting" card), while the count above says 1. Each list also stops at 3 items with no "+N more". Done: one card per task with both badges and times, in time order; after 5, a "+N more" link opens the Tasks (or Events) page
- [x] LINE messages clean the text formatting a little differently from the editor: they also remove `==` (not a format the editor has, so "x==1" arrives as "x1"), and a strikethrough that spans two lines keeps its `~~` marks. Suggest: let the LINE functions use the same rules as `src/lib/inlineFormat.ts`
